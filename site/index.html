Slack can wait. This account can’t.

Support loops. SLA turns red. An agent hits needs_human. Health stalls before renewal. Chat notifications hide. Phone doesn’t — if the call is rare, short, and for the right person.

One engine. Four cues.

  1. Cue arrives (fixture or event)
  2. Call sheet — owned? severity? house dark?
  3. Dress rehearsal by default — or curtain up
  4. Line reading 1 / 2 / 3 on the CS phone
  5. Prompt book + show report writeback

How judges run this

Clone → dress rehearsal (no key) → optional curtain-up.

git clone https://github.com/assafbar2/customer-success-voice-signal-hackathon.git
cd customer-success-voice-signal-hackathon/skills/customer-success-voice-signal
npm install

# Dress rehearsal — default, no ring
npm run signal -- --fixture stuck_support_acme.json
npm run signal -- --fixture agent_needs_decision_acme.json
npm run signal -- --list

# Curtain up — real CALL-E (operator only)
# Key: https://dashboard.heycall-e.com/account/api-keys
# cp .env.example .env  → CALLE_API_KEY + CS_OWNER_E164
npm run signal -- --fixture stuck_support_acme.json --live PLACES

Exit codes: 0 ok · 2 HOLD · 3 failure. Never commit .env.

Already rung. Already decided.

  • stuck_support live → 1 Take over in chat
  • agent_needs_decision live → 1 Approve A (exception)

Callee is always the CS owner. Customer never gets this call.
